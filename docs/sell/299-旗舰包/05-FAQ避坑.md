# 真机问题排查手册（现象 → 原因 → 处理）

这份 FAQ 里的问题都是在真实项目上线过程中实际遇到过的。每条按「看到什么现象、为什么会这样、怎么处理」组织，遇到问题时直接按现象查。

---

## 一、广告错误码对照

在广告的 `onError` 回调或 `show()` 失败时打印 `errCode`，对照下表判断问题出在哪一方。

| 错误码 | 含义 | 你该做什么 |
|--------|------|------------|
| 1000 | 后端接口调用失败 | 稍后重试，一般是临时问题 |
| 1001 | 参数错误 | 检查 adUnitId 是否填错、有没有多余空格 |
| 1002 | 广告单元无效 | adUnitId 拼错了，或者不属于这个 AppID |
| 1003 | 内部错误 | 稍后重试 |
| 1004 | 暂时没有合适的广告 | **最常见，不是你的错。** 提示「暂无广告，稍后再试」，不要让游戏卡住 |
| 1005 | 广告组件审核中 | 等待审核 |
| 1006 | 广告组件被驳回 | 去流量主后台看驳回原因 |
| 1007 | 广告组件被封禁 | 去流量主后台查看处罚原因 |
| 1008 | 广告单元已关闭 | 在流量主后台重新开启 |
| 2001 | 启动后短时间内不允许展示插屏 | 延迟几秒再弹，并按间隔重试 |
| 2002 | 距上次插屏展示时间太短 | 加大插屏冷却时间 |
| 2003 | 当前正在展示其他广告 | 不要在激励视频播放期间调插屏 |
| 2004 | 广告渲染失败 | 重试一次，仍失败就跳过 |
| 2005 | 广告调用异常 | 检查调用时机，比如实例是否已被销毁 |

错误码含义以微信官方文档为准；遇到表里没有的码，先去官方文档搜。

## 二、广告关闭后的真机问题

这一类问题在开发者工具里基本不出现，只在真机上发生，所以最容易漏到线上。

### 关掉广告后黑屏，或画面停住不动

**原因**：广告弹出时，微信会把小游戏当作切到后台，触发 `onHide`；广告关闭时触发 `onShow`。如果你在 `onHide` 里暂停了渲染循环，而 `onShow` 没有可靠地恢复，画面就停住了。部分机型上，从广告返回后画布本身也需要重新设置尺寸才能正常显示。

**处理**：

1. 激励和插屏展示前，由你自己主动暂停渲染，并标记「正在展示广告」。
2. 广告关闭后，由你自己主动恢复渲染，不要只依赖 `onShow`。
3. 关闭后等待约半秒，再检查画布尺寸是否和屏幕一致，不一致才重新设置。不要反复设置 `canvas.width`，连续设置会让关卡卡死。

### 广告一弹出，游戏就误以为切后台了

**原因**：广告刚弹出时，微信往往会在极短时间内连续触发 `onHide` 和 `onShow`，这不是玩家真的离开了。

**处理**：给 `onHide` 加一个短延迟（示例项目用 120 毫秒）。如果延迟内又收到了 `onShow`，就当作误报，什么都不做。离开时长不足约 350 毫秒的，也按误报处理。

### 关掉广告那一下，点击穿透到棋盘上，自动走了一步

**原因**：玩家点「关闭」的那次触摸，在广告消失后被游戏画布收到了。

**处理**：广告关闭后的短时间内（示例项目真机用 800 毫秒）忽略所有触摸输入。

### 关掉广告后背景音乐没了

**原因**：广告播放时系统暂停了游戏音频，回来后不会自动继续。

**处理**：广告关闭后，如果玩家没有开启静音、且背景音乐之前在播放，就主动恢复播放。

### 大厅横幅刚出来，大厅就黑屏

**原因**：原生模板广告创建并插入页面时，部分情况下也会触发 `onHide`，游戏按切后台处理把画面停了。

**处理**：创建横幅后的一小段时间内（示例项目用 1.6 秒）忽略 `onHide`。

### 点开游戏圈后弹出「微信无响应」

**原因**：游戏圈等原生页面要 1～2 秒才打开，这期间游戏还在全速渲染，主线程被占满。

**处理**：在点击按钮的那一刻就主动暂停渲染，不要等 `onHide`。

## 三、广告逻辑问题

**激励看完了却没发奖**
只认 `isEnded` 导致的。流量主后台设置的最长观看时长短于广告片长时，看够了关掉 `isEnded` 也可能为 `false`。改为：`isEnded` 为真，或者展示时长达到你后台设置的时长，都发奖。

**一次看完发了两次奖**
同一广告位重复创建了实例，或者每次展示都注册新的 `onClose` 却没有注销旧的。每个广告位只创建一个实例，每次展示结束后注销本次注册的回调。

**激励按钮点了没反应**
`show()` 失败后没有兜底。先尝试 `load()` 再 `show()`，仍失败就提示玩家，并且一定要让等待状态结束，否则界面会一直卡在「加载中」。

**进了关卡，大厅横幅还挂在屏幕上**
横幅的显示请求先发出，玩家随后进了关卡，横幅这时才加载出来。在加载完成的回调里再检查一次当前是否还在大厅，不在就立即隐藏。

**启动插屏的展示率很低**
没有处理 2001。先让大厅画出来，延迟 2～3 秒再调用；遇到 2001 隔几秒重试；设一个总超时，超时或进关就放弃。

## 四、开发者工具特有的问题

这些问题只在开发者工具里出现，真机正常，**不要为了它们改业务逻辑**：

- 原生模板广告报 `insertTextView`、`removeImageView not found`
- 激励或插屏创建时报 `updateTextView:fail`
- `onHide` 之后模拟器画面停死：开发者工具环境下不要在 `onHide` 里暂停渲染
- 重新设置 `canvas.width` 导致模拟器卡死：开发者工具环境下跳过画布重建

建议在代码里判断当前是否运行在开发者工具中（例如通过系统信息里的平台字段），对以上行为分别处理。

## 五、审核与备案

**因广告被拒**：检查有没有诱导文案、假关闭按钮，确保不看广告也能重试或返回大厅，并在审核说明里写清每类广告的用途。

**因名称被拒**：备案名、公众平台名称、游戏内标题三处统一。

**备案截图被打回**：场景、玩法、系统模块使用了同一张截图，或者截图里的游戏名和备案名不一致。

**系统功能被质疑**：纯广告游戏不要勾选或描述商城、虚拟货币、VIP。

## 六、包体与启动

**主包超限**：检查上传忽略列表，`node_modules`、源码、测试、文档、source map 都不应上传；大图和音频改为分包或远程加载。

**白屏**：入口文件没有重新构建、基础库版本过低，或启动时抛了异常。真机上打开调试，看第一条报错。

**刚上线没有收益**：先确认正式版确实发起了广告请求、广告位状态正常；填充率受地区、时段影响，上线头几天数据波动很正常。
