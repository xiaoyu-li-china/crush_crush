# 分层架构与广告策略

教程告诉你「广告怎么挂」，这一章讲的是「怎样组织代码，广告才能长期稳定地挂着」。纯广告游戏上线后，你会不停地调广告频率、换广告位、应对微信接口变化。如果广告调用散落在各个按钮里，每次调整都是一次全项目排查。

---

## 1. 分层：只有一个地方能碰 `wx`

```
界面层       只负责按钮显隐，调用 ads.show('rewarded_revive')
   ↓
玩法逻辑层   决定「这关要不要弹插屏」「失败给不给复活」，不调用 wx
   ↓ 依赖接口
适配层       唯一调用 wx.createRewardedVideoAd 等接口的地方
```

和广告相关的四个位置：

| 位置 | 负责什么 | 示例 |
|------|----------|------|
| 配置文件 | 广告位 ID 和频控数值 | `everyNLevels: 2`、`cooldownSeconds: 60` |
| 策略类 | 纯判断逻辑，可以单元测试 | 「第 4 关通关、距上次插屏 70 秒 → 弹」 |
| 广告适配器 | 创建、加载、展示、隐藏、销毁 | 封装激励、插屏、横幅三种 |
| 界面 | 根据结果更新画面 | 「看完了 → +5 步」 |

**回报**：

- 调频率：改配置里的一个数字
- 换广告位：改配置里的 ID
- 微信接口变化：只改适配器一个文件
- 策略可以在电脑上用单元测试覆盖，不用每次开真机

## 2. 统一的广告接口

所有广告位都通过同一个接口调用，`show()` 只返回四种结果：

| 结果 | 含义 | 界面该做什么 |
|------|------|--------------|
| `completed` | 看完了（或插屏正常关闭） | 发奖 |
| `skipped` | 激励中途关掉 | 不发奖，可以提示「看完才能获得奖励」 |
| `error` | 展示失败 | 提示稍后再试 |
| `not_ready` | 没有可用广告 | 提示暂无广告，按钮可以置灰 |

界面只看这四种结果，不需要知道微信的错误码和回调细节。**发奖只在 `completed` 分支里做**，这条规则写死在一个地方，就不会出现某个按钮忘了判断的情况。

## 3. 前后台：比广告接口本身更难的部分

真机上，广告弹出和关闭会触发小游戏的 `onHide` / `onShow`，而且触发方式并不干净：

- 广告刚弹出时，`onHide` 和 `onShow` 可能在极短时间内连续触发（误报）
- 原生横幅创建时也可能触发 `onHide`
- 广告关闭后，画布可能需要重设尺寸，点击可能穿透，背景音乐不会自动恢复
- 开发者工具里在 `onHide` 时暂停渲染、或重设 `canvas.width`，会让模拟器卡死

如果只是简单地「`onHide` 暂停、`onShow` 恢复」，就会出现黑屏、点击失灵、关广告误走一步这类线上问题。

推荐把这些情况收拢到一个「前台闸门」里统一处理：

| 事件 | 处理 |
|------|------|
| 激励 / 插屏开始展示 | 主动暂停渲染，进入「广告遮罩中」状态；这期间的 `onHide` / `onShow` 一律忽略 |
| 广告关闭 | 主动恢复渲染；等约半秒检查画布尺寸，不对才重设；约 0.8 秒内屏蔽点击；未静音则恢复背景音乐 |
| `show()` 立刻失败 | 直接恢复，不走画布重建流程 |
| 普通 `onHide` | 延迟约 120 毫秒才暂停；延迟内收到 `onShow` 视为误报 |
| 横幅刚创建 | 约 1.6 秒内忽略 `onHide` |
| 点击游戏圈等原生页 | 点击当下立即暂停，不等 `onHide`，避免「微信无响应」 |
| 开发者工具环境 | 不在 `onHide` 时暂停，不重设画布 |

这些数值来自示例项目在真机上反复调试的结果，可以作为起点，再按你的机型测试微调。代码见 08。

## 4. 广告策略设计原则

1. **奖励明确**。「看广告 +5 步」比「看广告抽奖」转化更稳定，也更容易过审。
2. **主路径不依赖广告**。广告是加速和续命，不看也能重试、回大厅。
3. **插屏放在停顿点，并且不打断连胜**。每 2～3 关一次，加冷却，失败局不弹。
4. **横幅不挡操作**。只放大厅；进关立即隐藏，并防止横幅加载迟到出现在关卡里。
5. **一个广告位一个实例**。重复创建会让回调叠加，导致一次看完发多份奖励。
6. **展示后立即预加载下一条**，玩家第二次点击时不用等。

## 5. 收入和留存的取舍

| 更激进 | 更稳妥 |
|--------|--------|
| 每关都弹插屏 | 每 2～3 关一次，加冷却 |
| 失败必须看广告才能继续 | 看广告可以续命，也可以直接重开 |
| 大厅和关卡都有横幅 | 只在大厅 |

上线后，把**广告收入和次日留存放在一起看**。收入上去了但留存明显下降，长期算下来是亏的，应该降低插屏密度。

## 6. 测试分层

| 测什么 | 怎么测 |
|--------|--------|
| 频控策略、发奖判定 | 在电脑上跑单元测试，覆盖所有分支 |
| 界面流程 | 用一个假的广告服务，固定返回 `completed` / `error` 等结果 |
| 前后台处理 | 把判断写成纯函数，单元测试覆盖；再上真机验证 |
| 真实广告 | 真机：低端机、弱网、无广告填充、看到一半切后台 |
