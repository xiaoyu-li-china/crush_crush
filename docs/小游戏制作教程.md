## 1. 产品与变现定位

本项目是一款竖屏休闲小游戏：

| 项 | 本项目选择 |
|----|------------|
| 品类 | 步数制三消闯关 + 通关限时粉碎加分 |
| 主题 | 萌宠 / 糖果风大厅 |
| 变现 | **纯 IAA**（激励视频、插屏、大厅横幅），**无内购** |
| 运行环境 | 微信小游戏（基础库建议 ≥ 2.19.0，工程配置可用 3.x） |
| 渲染 | 原生 Canvas（非 Cocos；架构文档里的 Cocos 为早期愿景） |

核心循环（玩家视角）：

```
大厅选关 → 三消闯关 → 通关粉碎加分 / 失败看广告复活
                ↓
         结算（可插屏）→ 下一关 / 回大厅
```

广告与玩法的绑定关系（本项目已接）：

| 广告位 | 玩家场景 | 奖励 / 作用 |
|--------|----------|-------------|
| 激励 · 复活 | 失败 | +5 步继续 |
| 激励 · 道具空仓 | 局内道具按钮为空 | 看完立即补给 |
| 激励 · 粉碎加时 | 粉碎阶段 | +5 秒 |
| 插屏 · 结算 | 通关结算 | 约每 2 关、冷却 60 秒 |
| 插屏 · 启动 | 进大厅后延迟展示 | 曝光 |
| Banner · 大厅 | 大厅底部原生模板 | 常驻曝光 |

玩法细节见 [`GAMEPLAY.md`](./GAMEPLAY.md)。

## 2. 账号与资质准备

按顺序准备，缺一环后面广告或提审会卡住。

### 2.1 微信小游戏账号

1. 打开 [微信公众平台](https://mp.weixin.qq.com/) → 注册 → 选择 **小程序**（小游戏同属该体系）。
2. 主体：个人可做休闲小游戏；若要开通更多能力（部分广告、支付等），企业主体更稳妥。本项目为 **无内购 IAA**，个人主体也可走流量主（以平台当时规则为准）。
3. 在「设置 → 基本设置」记录：
   - **AppID**
   - 小游戏名称（须与备案名一致，本项目备案名：**萌宠粉碎消**）
4. 把 AppID 写入 `project.config.json` 的 `appid` 字段（本仓库已是正式 AppID，本地勿用游客号测真实广告）。

### 2.2 类目与资质

- 选择合适的服务类目（如：游戏 → 休闲）。
- 按平台要求补充软著 / 版号说明：部分地区与品类对**版号、软著**要求不同，提审前在「设置 → 基本设置 / 类目」里按当前提示补齐材料。
- 纯广告无内购：系统功能描述里**不要**勾选虚拟货币 / 商城 / VIP（见备案文案）。

### 2.3 微信开发者工具

1. 安装最新稳定版 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 用管理员微信扫码登录。
3. 在公众平台「成员管理」把开发者加进项目。

### 2.4 流量主（广告联盟入口）

微信小游戏广告变现走 **流量主**，不是第三方「随便挂一个联盟 SDK」：

1. 公众平台 → **流量主**（或「推广」相关入口）。
2. 满足开通条件（累计 UV、类目、无严重违规等，以平台当页说明为准）后开通。
3. 开通后可创建广告位，拿到 `adunit-xxxxxxxx` 形式的 **广告单元 ID**。

> 本项目不接穿山甲 / AdMob 等外链 SDK；全部通过 `wx.createRewardedVideoAd` / `wx.createInterstitialAd` / `wx.createCustomAd` 走微信流量主。

## 3. 工程搭建与本地预览

### 3.1 环境

- Node.js ≥ 18
- 克隆本仓库后：

```bash
npm install
npm run build:wechat
```

成功后根目录生成 `game.js`（及 `game.js.map`）。

开发监听：

```bash
npm run dev:wechat
```

构建脚本：`scripts/build-wechat.mjs`，入口 `src/minigame/entry.ts` → 打包为 IIFE 的 `game.js`。

### 3.2 用开发者工具打开

1. 微信开发者工具 → **小游戏** → **导入项目**
2. 目录选仓库根目录（含 `game.js`、`game.json`、`project.config.json`）
3. 使用真实 AppID（测广告必须）
4. 编译 / 预览

详细操作见 [`WECHAT_DEVTOOLS.md`](./WECHAT_DEVTOOLS.md)。

### 3.3 关键命令

```bash
npm run typecheck          # TypeScript 检查
npm run test               # 逻辑 / 表现 / core 单测
npm run build:wechat       # 产出 game.js
npm run mahjong:ops-admin  # 若使用麻将馆运营后台
```

### 3.4 从零仿做时的最小骨架

若另起一个新游戏，建议保留本仓库的目录思想：

```
your-game/
├── game.json              # 小游戏配置（方向、超时等）
├── project.config.json    # AppID、打包忽略
├── package.json
├── scripts/build-wechat.mjs
├── src/
│   ├── minigame/entry.ts  # 入口
│   ├── core/              # 微信适配（广告/存储/音频）
│   ├── logic/             # 纯玩法（禁止 wx.*）
│   ├── presentation/      # Canvas / UI
│   ├── services/          # 组装注入
│   └── config/            # levels / ad-placements / balance
└── tests/
```

`project.config.json` 的 `packOptions.ignore` 应排除 `src/`、`tests/`、`docs/`、`node_modules/` 等，**只上传构建产物与必要静态资源**，否则包体爆、审核也慢。

## 4. 核心玩法怎么做

按本项目落地顺序（可当 checklist）：

### 阶段 A：盘面与三消

1. `BoardModel`：用紧凑结构存格子（本项目用类型化数组思路，见架构文档）。
2. `MatchFinder`：横竖 ≥3 同色。
3. `MatchResolver`：消除 → 下落 → 填充 → 连锁。
4. `MoveValidator`：相邻交换 + 非法回弹不扣步。
5. Node 单测覆盖死局、连锁、特殊块（**不依赖微信**）。

### 阶段 B：关卡与状态机

1. `levels.json` 配关：步数、目标、异形盘、障碍。
2. `GameStateMachine`：Lobby → PlayerInput → Resolving → Won/Failed → Crush → Settle。
3. HUD：步数、目标进度、分数。

### 阶段 C：通关增值与失败挽回

1. 剩余步数加成（MovesBonus）。
2. 粉碎奖励（CrushReward）：点击爆炸 + 可广告加时。
3. 失败激励复活（+5 步）。
4. 道具：锤子 / 重排 / 加步（空仓可看广告补给）。

### 阶段 D：大厅与社交

1. 选关地图、进度解锁。
2. 分享文案与图（`share-images.json`）。
3. 邀请、游戏圈、公告（按需接云函数）。

对照玩法表：[`GAMEPLAY.md`](./GAMEPLAY.md)。

## 5. 分层架构（推荐照抄）

**原则：逻辑层永远不要直接写 `wx.*`。**

```
Presentation（Canvas / UI）
        ↓ 发意图 / 订事件
Logic（三消、关卡、AdPlacementPolicy）
        ↓ 依赖 Port 接口
Core Adapters（WxAdAdapter、WxStorage…）
```

广告相关职责切分：

| 层 | 文件 | 职责 |
|----|------|------|
| Config | `src/config/ad-placements.json` | `adUnitId`、冷却、加时毫秒 |
| Logic | `src/logic/economy/AdPlacementPolicy.ts` | 第几关弹插屏、是否给复活入口 |
| Core | `src/core/adapters/WxAdAdapter.ts` | 真正调用微信广告 API |
| Service | `src/services/Bootstrap.ts` | 把配置注入 Adapter |

好处：换广告位 ID、改频控，只改 JSON / Policy；微信 API 变更只改 Adapter。

完整设计见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)。

## 6. 挂广告联盟（微信流量主）

### 6.1 开通流量主

1. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com/) → 进入该小游戏。
2. 开通 **流量主**（条件：类目允许、用户规模达标、账号状态正常等，以页面为准）。
3. 阅读并同意流量主协议。

### 6.2 创建广告位

在流量主后台创建与本项目对应的单元：

| 本项目 placement | 微信广告类型 | 建议命名 |
|------------------|--------------|----------|
| `rewarded_revive` | 激励式视频 | 复活 / 道具补给（可共用一个激励单元，也可拆两个） |
| `rewarded_crush_extend` | 激励式视频 | 粉碎加时 |
| `interstitial_settle` | 插屏广告 | 结算插屏（启动插屏复用同一单元亦可） |
| `banner_lobby` | 原生模板广告 | 大厅底部横幅 |

创建后复制 **广告单元 ID**（形如 `adunit-xxxxxxxxxxxx`）。

### 6.3 写入工程配置

编辑 `src/config/ad-placements.json`：

```json
{
  "rewarded_revive": {
    "adUnitId": "adunit-你的激励ID",
    "maxPerLevel": 0
  },
  "rewarded_crush_extend": {
    "adUnitId": "adunit-你的加时激励ID",
    "extraMs": 5000
  },
  "interstitial_settle": {
    "adUnitId": "adunit-你的插屏ID",
    "everyNLevels": 2,
    "cooldownSeconds": 60
  },
  "interstitial_launch": {
    "enabled": true,
    "delayMs": 2500,
    "retryMs": 2500,
    "timeoutMs": 45000
  },
  "banner_lobby": {
    "adUnitId": "adunit-你的原生模板ID",
    "enabled": true
  }
}
```

注意：

- 占位值若以 `TODO_` 开头或含 `UNIT_ID`，`WxAdAdapter` **不会创建广告实例**（方便本地调试）。
- 改完配置后执行 `npm run build:wechat`，再用**真机预览**测广告（开发者工具对原生广告支持不完整）。

### 6.4 代码侧已接好的能力（对照实现）

本项目 `WxAdAdapter` 已实现：

1. **激励视频**：`wx.createRewardedVideoAd`；关闭时按 `isEnded` 与「最少观看约 14s」综合判定发奖（适配流量主「最大激励时长」设置）。
2. **插屏**：`wx.createInterstitialAd`；结算 / 启动由 `GameSession` + `AdPlacementPolicy` 控制。
3. **大厅横幅**：`wx.createCustomAd`（原生模板）；进关会 `hide`，避免盖住棋盘。
4. **生命周期**：`onHide` / `onShow` 与展示看门狗，避免回调丢失导致卡死。
5. **dispose**：成对 `off*` + `destroy`，防监听泄漏。

业务侧约定：

- UI 按钮只调 `IAdService.show(placement)`。
- **只有 `completed` 才发奖**（补步、加时、道具）。
- `skipped` / `error` / `not_ready`：提示稍后重试，不发奖。

### 6.5 频控与体验建议

| 策略 | 本项目默认 | 说明 |
|------|------------|------|
| 结算插屏 | 每 2 关 + 60s 冷却 | 失败局不弹，减少「连关被堵」 |
| 启动插屏 | 延迟约 2.5s | 先让大厅可交互再弹 |
| 激励复活 | 可反复 | 纯 IAA 常见；若过猛可加每日上限 |
| Banner | 仅大厅 | 进关强制隐藏 |

改频控优先改 `ad-placements.json` 与 `AdPlacementPolicy`，不要在 UI 里写死。

### 6.6 真机验收广告

在真机预览中逐项点验：

- [ ] 失败 → 看广告 → 成功 +5 步；中途关闭不发奖（未达门槛）
- [ ] 粉碎 → 加时 → 时间增加
- [ ] 道具空仓 → 看广告补给
- [ ] 通关偶数关结算出现插屏；冷却内不再弹
- [ ] 大厅底部横幅；进关后消失
- [ ] 弱网 / 无填充：按钮提示不可用，游戏不崩溃

### 6.7 收益与结算

- 流量主后台查看曝光、点击、eCPM、收益。
- 结算周期与提现规则以微信官方为准（通常需绑定结算账户）。
- 禁止诱导点击、强制看广告才能继续主线过久等违规行为，否则会限流或封禁流量主。

## 7. 云开发与运营能力（可选）

本仓库已接微信云开发（`cloudfunctionRoot: cloudfunctions/`），用于：

- 邀请奖励记账

1. 开发者工具开通云开发，拿到 `envId`，写入 `src/config/cloud.json`。
2. 按 `cloudfunctions/README.md` 上传部署函数。
3. 在公众平台配置合法域名 / 云环境权限。

运营后台：`npm run mahjong:ops-setup` → 部署 → `npm run mahjong:ops-admin`。

## 8. 包体、分包与性能

微信小游戏主包有体积上限（常见要求主包 ≤ 4MB，以官方文档为准）。

本项目策略：

1. `packOptions.ignore` 排除源码、测试、文档、云函数源码目录等。
2. 大资源可走分包 / CDN（架构文档中的 `subpackages` 方案；`game.json` 可按需启用）。
3. 逻辑热点用对象池、避免每帧大量 `new`。
4. 真机低端机测：进关加载、连锁帧率、广告关闭后回前台。

发布前本地确认：

```bash
npm run build:wechat
# 在开发者工具「详情 → 本地代码」查看主包体积
```

## 9. 备案与合规

国内小游戏上架通常需要 **小程序/小游戏备案**（工信部联通微信侧流程）。本仓库已准备备案素材：

| 路径 | 用途 |
|------|------|
| `docs/beian-screenshots/备案文案.txt` | 场景 / 玩法 / 系统功能可复制文案 |
| `docs/beian-screenshots/上传分配说明.txt` | 各模块截图分配 |
| `docs/beian-screenshots/*.png` | 按说明上传，模块间勿复用同一张图 |

要点：

1. 备案名称与游戏内标题一致（**萌宠粉碎消**）。
2. 无内购：系统功能勿写商城 / 货币 / VIP。
3. 截图须能体现真实玩法；审核若要求微信内实机截图，用预览包重截。
4. 用户隐私：`game.json` 已含隐私授权相关配置项；按平台要求补充《用户隐私保护指引》与弹窗。

同步准备：

- 软著或平台要求的权属证明（按类目提示）
- 适龄提示 / 防沉迷说明（若平台类目要求）

## 10. 提审与正式发布

### 10.1 发布前检查清单

- [ ] `npm run build:wechat` 最新产物已生成
- [ ] `project.config.json` 中 AppID、项目名正确
- [ ] `ad-placements.json` 已换成正式 `adunit-*`，真机广告验收通过
- [ ] 游客 / 测试号逻辑关闭；正式包进度按通关解锁
- [ ] 分享图、图标、加载图、简介文案齐全
- [ ] 类目、隐私指引、用户协议（如需）已配置
- [ ] 备案状态为已完成或平台允许的状态
- [ ] 云函数（若用）已部署到生产环境，envId 正确
- [ ] 开发者工具「上传」前看一眼主包体积与无用文件

### 10.2 上传代码

1. 开发者工具打开本项目 → 点击 **上传**。
2. 填写版本号与备注（建议备注：玩法变更 / 广告位 / 修 bug）。
3. 到公众平台 → **管理 → 版本管理**。

### 10.3 提交审核

1. 选中刚上传的开发版本 → **提交审核**。
2. 按表单填写：
   - 测试账号（若需登录）
   - 主要玩法路径（可参考备案玩法文案精简版）
   - 广告说明：激励用于复活/加时/道具；插屏用于结算；无强制诱导
3. 等待审核（通常 1～若干个工作日，以平台为准）。

### 10.4 发布上线

1. 审核通过后，版本管理里 **全量发布**（或先灰度）。
2. 发布后立刻用正式版扫码自测：冷启动、进关、广告、存档。
3. 流量主后台确认有曝光数据（可能有延迟）。

### 10.5 体验版 / 灰度

- **体验版**：给内部与外部测试（二维码），适合广告与云函数联调。
- **灰度发布**：先放量一部分用户，看崩溃与投诉再全量。

| 周期 | 事项 |
|------|------|
| 每日 | 看流量主收益异常、用户反馈、致命报错 |

## 12. 常见问题

| 问题 | 处理 |
|------|------|
| 白屏 | 先 `npm run build:wechat`，确认有 `game.js` |
| 改了 TS 无变化 | 重新 build，或开着 `npm run dev:wechat` |
| 开发者工具广告报错 / Banner 异常 | 真机预览；工具对原生广告支持差 |
| 激励看完不发奖 | 检查 `completed` 判定；流量主「最大激励时长」与 `REWARDED_MIN_WATCH_MS` |
| 插屏一直 `not_ready` | 填充不足、冷却、或未 onLoad；看控制台 `interstitial` 日志 |
| 游客 AppID 无广告 | 换正式 AppID 并开通流量主 |
| 主包过大 | 检查 `packOptions.ignore`；大图进分包或 CDN |
| 审核拒：广告 | 去掉诱导文案；保证可跳过主路径；说明激励用途 |
| 审核拒：备案/名称 | 游戏内标题与备案名统一 |

更多调试说明：[`WECHAT_DEVTOOLS.md`](./WECHAT_DEVTOOLS.md)。
