# 萌宠麻将馆 · V1.2 后台 / 运营配置

## 1. 配置来源（优先级）

1. **CDN**（推荐）：`src/config/mahjong-cdn.json` 中 `enabled=true` 且填写 `opsConfigUrl`（JSON 结构与 `src/config/mahjong-ops.json` 相同）。示例见 `src/config/mahjong-ops.remote.example.json`。
2. **微信云库**：集合 `mahjong_ops`，文档 `_id=config`，字段 `config` 为完整 JSON。客户端通过云函数 `getMahjongOps` 拉取（CDN 未命中时）。
3. **包内默认**：`src/config/mahjong-ops.json`。

主题包仍走 `manifestUrl`，与运营配置独立。

## 2. 一键准备（本地，已可执行）

```bash
npm run mahjong:ops-setup   # 生成 Token、.env.local、部署清单与测试 JSON
npm run mahjong:ops-admin   # 可视化编辑 + 发布
```

`mahjong:ops-setup` 输出见 `tools/mahjong-ops-admin/generated/DEPLOY-CHECKLIST.txt`（含需在开发者工具里完成的步骤）。

## 2.1 可视化后台（本地）

```bash
npm run mahjong:ops-admin
```

浏览器打开 **http://127.0.0.1:8765**：

- 分栏编辑经济、生成、主题、关卡覆盖、抽检与广告
- **校验并归一化**：与客户端 `normalizeMahjongOps` 一致
- **运行抽检**：本地跑 1…3000 可解性（与 `mahjong:ops-sample` 同逻辑）
- **下载 JSON**：上传 CDN 的 `opsConfigUrl`
- **复制 setMahjongOps 参数**：在云开发控制台 → 云函数 `setMahjongOps` → 测试，粘贴 JSON（需先配置环境变量 `MAHJONG_OPS_ADMIN_TOKEN`）
- **写回包内**：仅开发机，更新 `src/config/mahjong-ops.json`

源码目录：`tools/mahjong-ops-admin/`。

### 本仓库云调用现状（已核对）

| 方式 | 项目里有没有 |
|------|----------------|
| 小游戏内 `wx.cloud.callFunction` | 有（存档 `player_saves`、`getMahjongOps`、`leaderboard` 等） |
| 云函数 HTTP 触发 URL | **仓库未预配**，需在[云开发控制台](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloud/guide/functions.html)为 `setMahjongOps` **手动开启**「HTTP 访问 / 云接入」后才有 URL |
| 固定运维 IP | **无**；走 HTTPS URL + `MAHJONG_OPS_ADMIN_TOKEN` 即可 |
| 自建 `server/` HTTP 服务 | **无**（`challenge.json` 里 HTTP 仅为排行榜预留，当前 `provider: cloud`） |
| 微信 OpenAPI `tcb/invokecloudfunction` | 需服务端 `access_token`，不适合浏览器直连 |

**推荐发布路径**：控制台开启 `setMahjongOps` 的 HTTP 访问 → 把 URL 填进可视化后台 → **一键发布到云（HTTP）**（经本地 `serve.ts` 转发，避免浏览器 CORS）。

请求头：`Authorization: Bearer <MAHJONG_OPS_ADMIN_TOKEN>`，Body：`{"config":{...}}`。

## 3. 云开发初始化

1. 上传并部署云函数 `initMahjongOps`、`getMahjongOps`、`setMahjongOps`（写入需配置 `MAHJONG_OPS_ADMIN_TOKEN`）。
2. 在云控制台调用 `initMahjongOps`（可传入 `event.config` 覆盖默认）。
3. 将集合 `mahjong_ops` 设为**所有用户可读**（或仅云函数读，客户端只走 callFunction）。
4. 后续改配置：在控制台编辑 `mahjong_ops/config` 的 `config` 字段，或重新调用 `initMahjongOps` 并传入新 JSON。

## 4. 可配项摘要

| 区块 | 用途 |
|------|------|
| `economy` | 金币兑换道具/重玩单价、三消得星/得币 |
| `session.timeoutSec` | 默认倒计时（秒） |
| `generation` | 种子版本、生成重试次数、105/9 张、种类数区间 |
| `theme` | L1/L2 固定主题、3000+ 主题循环、顺序/随机 |
| `levelOverrides` | 单关卡点：主题、种类数、限时 |
| `sampling` | 客户端与 CI 每 N 关可解性抽检 |
| `ads.rewardedVideoSlot` | 是否开放视频第 7 槽 |
| `tools.freeToUse` | 道具免费（预留，当前逻辑仍免费） |

## 5. 抽检与通过率

- **CI / 运维本地**：`npm run mahjong:ops-sample`（默认 1…3000，每 50 关 + 第 1 关）。失败 exit 1。
- **线上埋点**：新开关时若命中抽检，上报 `mahjong_ops_level_sample`（含 `solvable`、`opsVersion`）。
- **胜率/失败率**：沿用 `mahjong_level_win` / `mahjong_level_fail`（含 `reason`），在分析平台按关卡聚合。

## 6. 配置热更新埋点

- 成功：`mahjong_ops_config_ok`（`source`: `cdn` | `cloud`，`version`）
- 失败：`mahjong_ops_config_fail`（沿用包内配置）
